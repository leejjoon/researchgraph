# Acceptance scenarios
One file per operation (`attach.md`, `link.md`, `init.md`, `import.md` included, plus `notes-and-pins.md` for the relation edges, `queries.md`, and `general.md` for rules every write shares). Each scenario is Given / When / Then and maps to at least one test in `tests/`. "the research profile" means a fresh `rgraph init --profile research` project with one commit. Actors: `alice` (human, declares role `owner`), `bob` (human, declares role `reviewer`), `agent1` and `agent2` (agents). Tests fix `now` (`--now`) so lease and interval arithmetic is deterministic. Every scenario must also pass with the index deleted before the When step, and through the CLI as well as the Python API (T15).

In v0.2 every operation scenario also passes through MCP once T09 lands and HTTP once T11 lands, in both cache modes. This includes init/import/export and all permission/error branches, not just a digest smoke test. Reusable adapters expose CLI-equivalent results; transport-specific framing, cancellation, security, filesystem and installed-package checks remain additional coverage. The executable scenario inventory must identify each scenario's test and door coverage. New contracts: gates.md, graph.md, profile.md, events.md, mcp.md and serve.md. Spec-first scenarios do not claim their runtime implementation exists yet. Deterministic replay is a CI gate, not a real Claude Code/Codex CLI recording or outside-researcher session.
