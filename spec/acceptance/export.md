# export
1. Given any project with ≥ 50 nodes and history. When alice exports to `out.tar.zst` and it is imported into an empty directory. Then `graph/` and `.researchgraph/profile.yaml` are byte-identical to the source and `.researchgraph/history.jsonl` to the archive member; every query, including `--as-of` for any time recorded in `history.jsonl`, returns the same result in both projects, with and without the index, except that `history` attributes approval records, artifact records and `supersedes` records to the `rg: import` commit, while status intervals keep the archive's commit ids.
2. When exported with `--since <t>`. Then only nodes and edges changed after `t` are included, plus both endpoints of every included edge, plus everything reachable from that set by `supersedes`, `cites`, `derived-from`; importing the archive satisfies I5.
3. Given a read-only project. When bob exports. Then success (export is a read).
4. When the same project is exported twice with the same arguments, including any `--since` or `--as-of`, once with the index kept and once with it deleted first. Then the two archives are byte-identical.
5. Given attached artifacts with a 101-character ASCII basename and a Unicode basename under `artifacts/<node id>/`. When exported with `include_artifacts: true` and imported at a valid `now`. Then both paths, bytes and artifact records survive unchanged; the archive uses the canonical PAX headers in `store-layout.md`, and repeated exports are byte-identical.
6. Given the same graph and artifact bytes in two checkouts with different filesystem mtimes, ownership and permissions. When both export with `include_artifacts: true`. Then the archive bytes are identical, including automatically generated PAX headers; canonical-header fixtures cover a long path, a Unicode path and a header-only file size beyond USTAR's limit without allocating its payload.
7. Given T1 claimed by agent1 at t1 and completed at t2, Hypothesis H2 proposed at t3 and `cites C1 → R1` linked at t4, with t1 < T < t2 < t3 < t4. When alice exports with `--as-of T` and imports it into an empty directory. Then the archive has no member for H2 or the `cites` edge; T1's member is byte-identical to the source's current file (`done`, `lease: null`, with its `claim` and `complete` records); `history.jsonl` carries T1's `active`, `running` and `done` intervals; the import succeeds; and `show T1 --as-of T` reports `running`, `lease: null`, `lease_expired: false` and `ready: false` in both projects.
8. Given any project with ≥ 50 nodes and history. When alice exports with `--as-of t` for a time `t` recorded in `history.jsonl` and imports it. Then the archive's `graph/` members are exactly the nodes and edges in effect at `t`, each byte-identical to the source's current file; and every query under `--as-of t′`, for every `t′ ≤ t` recorded in `history.jsonl`, returns the same result in both projects, with and without the index, under the exceptions of scenario 1.
9. When exported with `--since s --as-of t` (s < t). Then the changed set is exactly what `since s --as-of t` reports, extended by endpoints and closure as in scenario 2; importing satisfies I5; and the archive is byte-identical to one produced with the index deleted first.
10. Given H1 superseded by H1′ with `--no-commit`, then H1′ tagged with `--commit`. Then at the source `history H1′` reports the `supersedes` record with `commit: null` and H1′'s first status interval with the tag commit. When alice exports and imports. Then in the imported project `history H1′` reports the `supersedes` record and every approval and artifact record with the `rg: import` commit, every status interval with the archive's commit ids, and is otherwise identical to the source's; the same holds after `rm index.sqlite`.
