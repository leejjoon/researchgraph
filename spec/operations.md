# Operations (normative)

Every graph operation has the same logical name and arguments across four doors: Python, installed CLI, MCP and HTTP (the latter two introduced in v0.2). Each is marked **read** or **write**. A project opened read-only refuses every write with `RuleViolation(rule="read_only")`.

Every call carries an `actor` (`data-model.md` §2.1) and an optional declared `role`. The CLI derives a human actor from `git config user.name` and `user.email` unless `--as-agent NAME[:MODEL[:VERSION]]` is given; `--role ROLE` declares a role for the call. Roles are self-declared; the profile only lists which role names exist and which gates they satisfy. Every call also takes `now` (CLI `--now`, default wall clock) which is the timestamp written and the clock for the predicates in `data-model.md` §6.

Errors are `RuleViolation{rule: str, message: str, ids: [str]}`; the CLI prints them as JSON on stderr and exits 2. Nothing is written on a validation error; the only exceptions are `write_failed` after a mid-write or commit failure (`store-layout.md`, Writes). When several rules apply, the shared rules are checked first in the order listed above (`read_only`, `clock_skew`, `not_found`, `profile_too_new`, `human_only_approval`, `wrong_role`, `unsupported_by_profile`), then the row's rules in the order listed, except where a row says otherwise; `artifact_path` precedes `artifact_missing`. Edges may be created to or from retired nodes; no rule forbids it. Every write may raise, in addition to the rules listed per row: `read_only`; `clock_skew` (`store-layout.md`, `--as-of`); `not_found` (an id argument does not exist); `profile_too_new`; `human_only_approval` (an agent calls a write whose *Allowed to* is `human`); `wrong_role` (the declared role is not one the operation or gate accepts); `unsupported_by_profile` (`data-model.md` §8); `write_failed` (`store-layout.md`, Writes).

Where an operation records something, the record is the `approvals` entry defined in `data-model.md` §2.2, and generated nodes are filled per §2.3.

## Doors (decision 017)

Python uses `Project.<op>(...)`; the pinned profile read is `Project.profile_info()` because `Project.profile` is the loaded profile object. The CLI uses `rg <op>` with `--json`, MCP uses tool `<op>`, and HTTP uses `GET /api/<op>` for reads and `POST /api/<op>` for writes. Structured/repeated HTTP read arguments use JSON-encoded query values; writes use a JSON object. `GET /api/operations` publishes the registry. Import/export retain their operation semantics and filesystem arguments; adapters do not silently replace them with unrelated transport operations. Results are CLI-equivalent JSON; omission and explicit null remain distinct. HTTP maps RuleViolation `{rule, message, ids}` to 422, project-open errors to 503 and authority failures to 403. Adapters call shared operations, never SQL or a second business-validation layer.

The registry contains exactly 37 graph Writes/Reads (18 writes, 19 reads), including graph and profile. Streams and Servers are separate categories. Their installed rows and manual references land in their introducing commits; semantic contracts alone do not advertise unimplemented commands.

MCP uses the official optional SDK over stdio. Launch requires `--as-agent NAME[:MODEL[:VERSION]]` or explicit `--as-human`, and fixes actor, role and read-only for the process. Tool arguments cannot override authority or choose another project. Full is default; essential lists exactly show, ready, blocked, queue, digest, where, history, evidence, propose, link, attach, claim, renew, release, complete, fail. Read-only intersects the preset, hides all writes and refuses attempted hidden writes including init/import. Tool descriptions/schemas come from the registry and `readOnlyHint` from kind. Instructions equal profile `agent_guidance`, never core prompts. Results include CLI-equivalent JSON in text and `structuredContent`; RuleViolation uses `isError` with its structured JSON. No stdout logging; close per-request owners and all resources on cancellation/shutdown. Help/core import work without the extra; invoking a missing extra reports an actionable error.

The optional Starlette/Uvicorn HTTP server binds loopback and fixes writes to the serving human's git identity. Roles are self-declared per request; read-only cannot be disabled by a request. One Project lock serialises requests and polling; it does not turn read-only reads into write-lock operations. Server shutdown/disconnect closes owners and subscriptions. Same-origin embedding only.

### Graph and profile read contracts

Graph returns `{nodes: [...], edges: [...]}` including retired records, each list ordered by `(created, id)`. Node objects match show projections without show-only incident/derived additions. It honours existing as-of limitations, leaves files and Git unchanged, and returns the same state after index deletion. Report production and parse time for 20k-node JSON without inventing a new budget.

Profile returns `{name, version, installed_version, node_types, edge_types, gates, roles, agent_guidance}`. Name/version are pinned; installed_version identifies the loaded package profile version. Node types are `{name, prefix, claimable, schema}`; edges `{name, allowed, inherit, schema}`; gates `{transition, node_type, roles, agents_allowed, when_fields}`. Preserve declaration order and unused declared types, effective core edge definitions and safe schemas. Never serialise validators, hooks, expansion hooks, renderers, migrations or other callables. All four doors use this shared data-only read, including `GET /api/profile`; there is no HTTP-only alternative. Under as-of it reports the currently loaded profile, not reconstructed historical declarations.

### Browser session and artifact authority

The launch URL is `http://127.0.0.1:PORT/#token=…`. The host removes the fragment immediately and exchanges the token once in a JSON `POST /api/session` body for an instance-lifetime, host-only `HttpOnly; SameSite=Strict` cookie. Reuse, a previous-instance token/cookie or query-string token is rejected. Protected API (including operations/profile), SSE and artifact routes require that cookie. Validate Host against the bound origin on every request; reject any foreign Origin, require the matching Origin for session exchange and mutation, and permit absent Origin only for same-host authenticated reads (including direct downloads). No permissive CORS. Foreign Host/Origin and unauthorised requests yield 403. Root/static bootstrap exposes no graph before authentication. Responses carry `Cache-Control: no-store` and `Referrer-Policy: no-referrer`; tokens/cookies never enter logs, DOM attributes, persistent browser storage or referrers.

`GET /artifacts/<node>/<path>` serves only an existing regular file whose project-relative path is registered in that node's artifacts and lies under `artifacts/<node id>/`. Validate percent-decoded paths with Project's safe-path boundary; reject plain/encoded/double-encoded traversal, absolute paths, wrong-node roots, unregistered files, escaping symlinks and path swaps with nondisclosing 404. Hold containment through opening, not resolve-then-reopen. Never list directories. Downloads use `Content-Disposition: attachment` with a safely encoded basename, `Content-Type: application/octet-stream` and `X-Content-Type-Options: nosniff`. HTML/SVG must remain inert attachments, not inline same-origin documents.

### Viewer controls

Show/history/evidence/weakest/alternatives/predictions/notes/subtree populate the inspector; where supplies filters; queue/blocked supply review cards; digest/stale/ready/where supply monitoring. Mutation controls map only to approve(note), reject(reason), instruct, one supersede(instruction) for re-run, retire, budget, tag, link(pins), expand. Expand creates a Task, never executes it. Send back is reject-with-reason, not a new lifecycle. Render text escaped; hide read-only actions but still enforce authority server-side. On mutation errors display the error and refetch persisted state without automatic retry; retained-byte failures can have effects.

Rank using Kahn's algorithm over non-retired I1 edges only: blocks, derived-from, supersedes, cites, part-of. Draw other/retired edges without rank constraints; collapse after ranking. Append unplaced nodes in created/id order so mixed-edge and invalid I1 cycles never lose nodes or hang. Pan/zoom/selection/collapse are presentation-only, no layout files. Runner capacity, instruction acknowledgement, budget/lease inheritance, selective edge transfer, diff, timeline scrubber, budget burn, since-last-look, renderers/notebook previews and standalone app remain deferred.

## Writes

| Op | Arguments | Effect | Allowed to (default) | Rules it can raise |
| --- | --- | --- | --- | --- |
| `init` | `path, profile` | Create the layout in `store-layout.md`, run `git init` if `path` is not a repository, write `profile.yaml` and `.gitignore`, make the first commit `rg: init`. | human | `already_initialised`, `unknown_profile` |
| `propose` | `type, title, body?, fields?, edges?: [{type, to|from, fields?}]` | Create node in `proposed` (or `active` if no activate gate matches its type and normalised/default-materialised immutable fields). Create the listed edges, each incident to the new node. | human, agent | `unknown_type`, `reserved_edge_type`, `schema`, `edge_endpoints`, `cycle`, `duplicate_edge` |
| `link` | `type, from, to, fields?` | Create one edge between two existing nodes. `supersedes`, `explains` and `instructs` are reserved for their operations. | human, agent | `reserved_edge_type`, `edge_endpoints`, `schema`, `cycle`, `duplicate_edge` |
| `approve` | `node, what?=activate, note?` | Record approval; if every matching activate gate is satisfied, `proposed → active`. Match the node's immutable materialised fields as in `profiles.md`. `what` must be `activate`. A second approval by the same actor on the same node raises `already_approved`. | human; a matching gate with `agents_allowed` admits agents, otherwise an agent gets `human_only_approval` (checked after `not_proposed`) | `wrong_role`, `not_proposed`, `already_approved`, `unknown_what` |
| `reject` | `node, reason` | `proposed → retired`; retire its non-retired edges; reason recorded. | human | `not_proposed` |
| `supersede` | `node, title?, body?, fields?, inherit_edges?: bool=true, instruction?` | Create the replacement (same type, §2.3), create `supersedes replacement → node`, set the old node `retired` and record `superseded`, retire each *transferable* edge (§3) and if `inherit_edges` recreate it from the replacement; leave every other edge untouched. If `instruction` is given, also create an Instruction node with `instructs → replacement`. | human for any type; agent for Task and Result only | `agent_cannot_supersede_type`, `terminal_status`, `running`, `cycle`, `schema` |
| `instruct` | `node, text` | Create an Instruction node (§2.3) and `instructs → node`. `node` must be `proposed` or `active`. | human | `already_ran` |
| `claim` | `node, lease_seconds=7200` | If `ready(node)`: set `status = running` and `lease = {actor, acquired_at: now, expires_at: now + lease_seconds}`, replacing any expired lease; record `claim`. | human, agent | `lease_held` (running with an unexpired lease; checked before `not_ready`), `not_ready`, `negative` (`lease_seconds < 1`) |
| `renew` | `node, lease_seconds=7200` | `expires_at = max(expires_at, now + lease_seconds)`; record `renew`. Holder only, even after expiry. | lease holder | `not_running`, `not_lease_holder`, `negative` (`lease_seconds < 1`) |
| `release` | `node, note?, usage?` | `running → active`, clear lease, add `usage`, record `release`. | lease holder or any human | `not_running`, `not_lease_holder`, `negative` |
| `complete` | `node, summary, artifacts?: [path], usage?` | `running → done`; for each path (relative to project root, under `artifacts/<node id>/`, existing) append an artifact record with its sha256 and size and stage the file in the commit; add `usage`; clear lease; record `complete`. | lease holder | `not_running`, `not_lease_holder`, `artifact_path`, `artifact_missing`, `negative` |
| `fail` | `node, summary, step?, check?, measured?, error?, usage?` | `running → failed`; create a Failure node (§2.3) and `explains → node`; add `usage`; clear lease; record `fail`. | lease holder | `not_running`, `not_lease_holder`, `negative` |
| `expand` | `nodes: [id], hint?` | Create one Expansion task (§2.3). The core never executes it. | human | `no_targets` |
| `budget` | `node, tokens?, compute_seconds?` | Set `budget` to exactly the given dimensions (an omitted dimension is removed); record `budget`. Zero means stop. | human | `negative` |
| `retire` | `node, reason` | `proposed|active|failed → retired` without replacement; retire its non-retired edges; record `retire`. | human | `terminal_status`, `running` |
| `attach` | `node, artifacts: [path]` | Append artifact records (as `complete` does) to any non-retired node, staging the files. | human, agent | `terminal_status` (retired only), `artifact_path`, `artifact_missing` |
| `tag` | `node, add?: [str], remove?: [str], priority?: int|null` | Edit `tags` and `priority`; `priority: null` clears it. No record. | human, agent | — |
| `import` | `archive, path` | Into an empty or non-existent directory: validate the archive and its import clock floor (`store-layout.md`, Import clock) before creating destination files; create `init`'s layout (without its commit) pinning the archive's profile, write `graph/`, `.researchgraph/history.jsonl` and any artifacts without rewriting their timestamps, then make one commit `rg: import`. | human | `not_empty`, `bad_archive`, `profile_too_new` |

Budget is enforced only as a query (`where --over-budget`) and a `ready` exclusion. The core does not meter tokens; consumers pass `usage` to `complete`, `fail` or `release`, and each call adds to the stored totals. Operation count: eighteen writes (`export` is a read).

The commit for a write touches only the files that write created or changed. Its message is `rg: <op> <id>` where `<id>` is the node argument for operations that take one (for `supersede` the old node, for `fail` the failed node), the new node's id for `propose` and `expand`, the edge id for `link`, the node for `attach`, and empty for `init` and `import`.

## Reads

| Query | Returns |
| --- | --- |
| `graph` | `{nodes: [...], edges: [...]}` including retired, each sorted by created/id; existing as-of projections apply, no show-only derived fields |
| `profile` | pinned name/version, installed_version and currently loaded node_types/edge_types/gates/roles/agent_guidance as data in declaration order, including unused types; no callables; as-of does not reconstruct historical profile declarations |
| `show <id>` | the node or edge; for a node also its non-retired incident edges, the Instruction nodes that `instructs` it, its pins, derived flags `blocked`, `ready`, `stale`, `lease_expired`, `over_budget`, and profile warnings such as `non_discriminating` |
| `ready` | nodes with `ready(n)` in `ready` order (§6) |
| `blocked` | nodes with `blocked(n)` and the ids blocking them, in `ready` order |
| `queue` | `proposed` nodes matching at least one activate gate, with the matching gates' roles and the approvals so far, oldest first; partial approvals keep the node queued until every matching gate is satisfied |
| `history <id>` | the `supersedes` edges of the chain in both directions (whether or not retired), then every `approvals` record, artifact record and status interval of every node in the chain, each edge and record with the commit that introduced it, oldest first |
| `evidence <claim>` | the closure of `claim` over non-retired `cites` then `derived-from` edges (every node reachable by any sequence of those edges), with artifacts; `claim` itself excluded |
| `stale` | claims with `stale(c)`, each returned once, in `created` then `id` ascending order, with `responsible: [id]`: all distinct replacement-head IDs sorted lexicographically. For every superseded input reachable through non-retired `cites`/`derived-from` edges, follow its non-retired incoming `supersedes` edge to the source repeatedly until reaching a node with no such edge. Deduplicate the heads across inputs and paths. Under `--as-of`, use the edges present at that time. |
| `weakest <claim>` | direct non-retired `cites` targets of every permitted type, sorted ascending by `(has no superseded input, fields.runs default 0, fields.held_out default false, id)`: superseded-input targets first, then fewer runs, then no held-out flag. A target has a superseded input when it, or any node reachable from it via non-retired `derived-from` or `cites` edges, has a non-retired incoming `supersedes` edge. Only Claim vocabulary is required, not Result or Reference. Supplied scoring values are validated on write (`runs` is an integer, not a boolean; `held_out` is boolean), never coerced; missing query defaults do not modify stored fields |
| `predictions <hypothesis>` | its incoming non-retired `tests` edges with source node, `expected`, `discriminating`, and the source's status, oldest first |
| `matrix <question>` | one row per source of a non-retired `tests` edge into any member of the exclusion group (Prediction or Task), one column per member (both in `created` order), cell = `expected` or empty, with `non_discriminating` per row (§6) |
| `alternatives <hypothesis>` | the union over every question it answers of the other members of that exclusion group, each with status and its non-retired `supports`/`contradicts` claims; `created` order |
| `since <time>` | nodes whose `created`, `updated`, any `approvals[].at` or `artifacts[].added_at` is after `time`, and edges whose `created` or `retired_at` is after `time` |
| `where <filter>` | `--type`, `--status`, `--author NAME`, `--field k=v` (string equality on `fields.k`), `--tag t`, `--text "..."` (title and body substring, case-insensitive), `--over-budget`; filters conjoin; `created` order |
| `notes <id>` | Note nodes with a non-retired `about` edge to the node, newest first |
| `subtree <id>` | the nodes in `subtree(id)` with status counts and summed usage |
| `digest` | counts and lists of: `running`, `ready`, `blocked`, `awaiting` (the `queue`), `failed_24h` (nodes whose status became `failed` within the 24 hours before `now`), `claims` (non-retired Claims) |
| `export` | `out, include_artifacts?: bool = false, since?` — write a tar.zst containing `graph/`, `.researchgraph/profile.yaml`, `.researchgraph/history.jsonl` (the status intervals), and optionally `artifacts/`. With `since`, only nodes and edges changed after `since` (as `since` defines changed), plus both endpoints of every included edge, then every node reachable from the included set by `supersedes`, `cites` and `derived-from`, together with the edges traversed. With `since`, `history.jsonl` carries only the included nodes' intervals. Under `--as-of`, the as-of time governs selection only (decision 015): the included nodes and edges are those in effect at that time (`store-layout.md`, `--as-of`), and with `since` the changed set is what `since` reports under the same `--as-of` (changes after `since` up to and including the as-of time); endpoints and closure are then added as above. Every archived `graph/` file and artifact file is the working-tree bytes of the selected member, and `history.jsonl` carries the selected nodes' complete status intervals, including intervals after the as-of time. An archive never contains a historical projection; a historical view of an imported project is obtained by querying it with `--as-of`. The archive is POSIX PAX with a member for every directory and file, using the canonical archive encoding in `store-layout.md` (decision 012), compressed with zstd level 3, so the bytes are deterministic across runs and machines. |

Every graph read accepts `--as-of <time|commit>`; `store-layout.md` says what is reconstructed, and for `export` the as-of time selects members without reconstructing their files (see the `export` row). A commit maps to its committer time. Streaming events describe current observations, not historical replay.

## Streams

| Stream | Arguments | Output |
| --- | --- | --- |
| `events` | `--follow`, `--since CURSOR`, `--poll-interval SECONDS` (positive finite, default 1) | One envelope per JSONL or human line; exit 0 on stdin close or SIGINT |

The events stream uses `--follow`, `--since CURSOR` and `--poll-interval SECONDS` (positive finite, default 1). JSON output is one event object per line; human output is one line per event. Follow exits 0 on stdin close or SIGINT. It is read-only and takes no writer lock. Each invocation starts a new generation, so a cursor from a previous invocation resets even with unchanged bytes. Python changes and CLI/SSE use the identical full cursor and reset semantics in `store-layout.md`, Change events.

MCP and HTTP launchers are added with their implementation, outside graph-operation counts. Launcher help works without optional extras. HTTP SSE uses `GET /api/events`, full cursor in both `id:` and `Last-Event-ID`, and 15-second keepalive comments; one-second polling must observe external CLI claims within three seconds under the required fifty-running-node load. Replay includes only retained successors; reset means refetch. Slow/disconnected clients cannot leak unbounded buffers or resource owners.

## CLI conventions
- `rg --project PATH` or run inside the project.
- For graph operations, `--json` emits one JSON object (or array) on stdout; without it, a human table. Streams use their separately documented line-oriented output. Node and edge objects use the YAML key names; `show` adds `edges`, `instructions`, `pins`, `flags` and `warnings`; `history` is a list of `{kind: interval|approval|artifact|supersedes, node, commit, at, ...}` oldest first; `matrix` is `{rows: [{source, cells: {hypothesis: expected}, non_discriminating}], columns: [...]}`; `subtree` is `{nodes: [...], status_counts: {...}, usage: {...}}`. `ready`, `blocked`, `queue`, `stale`, `evidence` and `digest` return `{items: [...]}` with node objects plus the extra keys their rows name (`blocking`, `gate`, `approvals`, `responsible`, `artifacts`, counts). These shapes are frozen at T15 for the v0.2 wrappers.
- `stale` items always contain `responsible` as an array of node IDs, including for a single cause; there is no scalar form.
- `--commit/--no-commit` on writes (default commit). Event hooks fire only after a commit.
- `--read-only` opens the project read-only for the whole invocation.
- `--as-agent NAME[:MODEL[:VERSION]]`, `--role ROLE`, `--now TIMESTAMP`.
- Structured arguments are JSON: `--fields '{"k": 1}'`, `--usage '{"tokens": 10}'`; `--edge '{"type": "tests", "to": "hy-..."}'` repeatable; `--artifact PATH` repeatable; `--tokens N --compute-seconds M` for `budget`.
- Exit codes: 0 ok, 2 RuleViolation (including `profile_too_new`), 3 project not found or invalid.
