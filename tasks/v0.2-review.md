# Review of the v0.2 work list

Date: 2026-10-21
Reviewed document: `tasks/v0.2.md`
Status: Review findings; not implementation approval. **All findings resolved 2026-10-21** by committee response and amendments to `tasks/v0.2.md` (see Resolutions below).

## Summary

The proposed scope and task ordering provide a solid foundation for v0.2. The optional server dependencies, shared operation contract, preservation of v0.1 invariants, explicit deferred scope, and distinction between deterministic replay and real agent usability evidence are sensible.

Five contract issues should be resolved before implementation. Two additional interface/security details should be specified in decision 017. This review does not challenge the deliberate conditional-gate and citation extensions merely because they differ from v0.1; those changes already have planned decision records.

The review was read-only. No implementation, test execution, specification changes, or new consensus workflow was performed. An independent architecture reviewer corroborated the inventory, citation fallback, and failed-write findings. The other findings below are the parent reviewer's analysis, not a claim of independent consensus.

## Findings

### 1. T07: Failed writes may leave observable changes — RESOLVED

**References:** T02 and T07; `spec/operations.md`, common error contract; `spec/store-layout.md`, Writes step 6.

T07 says that a failed write yields no events. However, the existing contract explicitly allows a commit failure to leave changed files written while raising `write_failed`. Such a failure is observable to other processes even though the operation returned an error.

Suppressing its events would contradict both state-derived polling and the invariant that applying observed events reproduces the current graph.

**Suggested resolution:** Define notifications by observable state, not operation success. Validation failures and fully rolled-back failures produce no domain changes. If a failed operation leaves changed files, the next observation reports the resulting diff or a reset.

**Acceptance clarification:** Include both a fully rolled-back failure and a commit failure with retained bytes. Verify a second Project and the event consumer converge to the actual persisted graph.

### 2. T12: The proposed layout edge union is not necessarily a DAG — RESOLVED

**References:** T12; `spec/data-model.md`, I1 and the subtree traversal definition.

T12 proposes topological layout over `blocks`, `derived-from`, `tests`, `addresses`, and `cites`. I1 guarantees acyclicity for a different edge set; it does not guarantee acyclicity for this union. The subtree definition explicitly accounts for cycles involving `tests` or `addresses`.

For example, a Hypothesis derived from a Prediction and that Prediction testing the Hypothesis can satisfy I1 while forming a cycle in the layout's edge union. Handling only cyclic `relates-to` edges is therefore insufficient.

**Suggested resolution:** Require a cycle-safe layout. Strongly connected component condensation followed by topological layout is one option; another explicitly defined cycle-safe algorithm is acceptable. Do not reject otherwise valid research graphs merely to simplify rendering.

**Acceptance clarification:** Add a valid mixed-edge cycle fixture and verify all nodes remain selectable and the viewer renders without hanging or dropping records.

### 3. T05–T06: Documentation inventory tests must change incrementally — RESOLVED

**References:** T05, T06, T08, T09, T11, T16; `tests/test_docs.py`, `spec_commands`, `help_commands`, `check_reference`, and installed-help inventory assertions.

The existing tests require a `Commands:` help section, assert the current 18-write/17-read inventory, and equate installed commands with only the Writes/Reads tables in the specification.

Consequently:

- T05 cannot introduce grouped Writes/Reads help while requiring documentation tests to pass unchanged.
- T06 adds `graph`, invalidating the current command counts.
- Later streams and server launchers appear in installed help but are deliberately outside the graph-operation inventory.

The inventory rule is useful, but corresponding test changes cannot wait until T16.

**Suggested resolution:** Assign help-parser, category, count, and coverage updates to the task that introduces each interface change. Preserve separate coverage for graph operations, streams, and servers. Here, passing tests should mean retaining complete coverage, not retaining obsolete assertions.

**Acceptance clarification:** Require the documentation inventory checks to pass after T05, T06, T08, T09, and T11 individually. Test missing entries in each category so separation does not weaken coverage.

### 4. T01/T04: Citation fallback semantics conflict — RESOLVED

**References:** T01 and T04; `spec/data-model.md`, section 8 reserved-vocabulary table; `spec/operations.md`, `weakest`.

T01 promises target-type-agnostic `evidence`, `stale`, and `weakest`, while also preserving the reserved-vocabulary table's behavior when built-in citation types are absent. The existing table says `weakest` returns empty without the relevant built-in types and describes scoring fields specifically on Result.

A profile declaring Claim and Literature, but neither Result nor Reference, exposes the contradiction: should its cited Literature be ranked or should the result be empty?

**Suggested resolution:** Decision 019 should explicitly update section 8. Define scoring defaults for all permitted citation target types, and state that profile-added citation targets remain queryable when Result and Reference are absent.

**Acceptance clarification:** Include a Claim/Literature-only profile and verify evidence traversal, staleness, and weakest ordering, including missing scoring fields. Do not rename or migrate immutable existing node types.

### 5. T02/T11: SSE does not transmit the full cursor — RESOLVED

**References:** T02 decision 020; T11 SSE resume behavior.

T02 defines a cursor as `(generation, seq)`, but T11 specifies SSE `id:` as only `seq` and resumes through `Last-Event-ID`. The missing generation information leaves the resume contract underspecified, particularly when sequence values can be reused after a server restart.

**Suggested resolution:** Define one opaque cursor representation shared by the Python/CLI event surfaces and SSE resume handling, or explicitly define how the SSE cursor maps to the full source cursor. Include source-instance or equivalent restart identity where necessary to prevent collisions.

**Acceptance clarification:** Reconnect with a valid cursor, a cursor outside retained observations, and a cursor from a previous server instance with an overlapping sequence value. Unknown or stale cursors must cause reset rather than silently miss changes.

## Additional details for decision 017

### Viewer profile metadata — RESOLVED

The viewer must obtain type order, role names, and gate definitions without hard-coded profile knowledge. The proposed `graph` response contains only nodes and edges, while `/api/operations` describes operations rather than the project's profile.

Specify how the server supplies safe, serializable profile metadata: for example, a dedicated read-only metadata endpoint or bootstrap payload. Include conditional gate definitions and types absent from the current graph. Do not serialize validators, hooks, or other Python callables.

### Artifact download security — RESOLVED

Path validation and escaped node text are necessary but do not by themselves define safe artifact serving.

Specify:

- Containment under the intended artifact root, including symlinks and encoded traversal attempts.
- Whether only registered artifacts may be downloaded.
- Download headers and content handling that prevent attached HTML/SVG from executing under the API server's origin, such as attachment disposition and content-type hardening.
- How the launch token is carried by API calls, downloads, and SSE, with appropriate protections against URL/log/referrer exposure.
- Negative tests for traversal, symlink escape, unauthorized access, and active-content artifacts.

These are boundary requirements, not a request for authenticated identities or an execution sandbox beyond the stated v0.2 scope.

## Recommended disposition

Amend the work list and planned ADR acceptance requirements to resolve the five findings and specify the two boundary details. A new full planning run is not needed solely to make these bounded corrections.

Do not begin implementation based on this review alone. Gate 2's real agent sessions, external researcher session, and cross-repository profile adoption remain distinct deliverables; passing local replay tests must not be substituted for them.

No GJC runtime or researchgraph product changes are included.

## Resolutions (committee response, 2026-10-21)

Both committee members (Claude Fable 5.1, Codex GPT-6-Astra) accepted every finding and both decision-017 details, and endorsed the recommended disposition. Where the review's suggested resolution had a cheaper alternative that still closed the finding, the cheaper one was taken. Amendments are applied verbatim to `tasks/v0.2.md`; the sentences for decision records 017–020 are carried in the affected items and land with T01/T02.

1. **Failed writes.** Accepted. Notifications follow observed state, never operation outcome: validation failures and rolled-back writes yield no node or edge events; a commit failure with retained bytes or a post-commit hook failure yields the same events as a `--no-commit` write, and a second `Project` and the consumer converge on the persisted graph. T13's "no partial replacement" clause is likewise limited to rolled-back failures. (T02, T07, T13; decision 020.)
2. **Layout cycles.** Accepted with a cheaper fix than SCC condensation: rows are ranked by Kahn's algorithm over the non-retired I1 edge set only; all other edges are drawn without constraining rank; collapsing is presentation-only; unplaced nodes are appended in `created, id` order. A mixed-edge cycle fixture joins the T12 done-when. (T12; decision 017.)
3. **Inventory tests.** Accepted with change: click's single `Commands:` section is kept and classification is published through the registry; each introducing item (T05, T06, T08, T09, T11) updates `tests/test_docs.py` in its own commit with one inventory per category and negative fixtures; launcher `--help` works without its extra. (Inventory rule, T05, T06, T08, T09, T11, T16; decision 017.)
4. **Citation fallback.** Accepted. Decision 019 rewrites `data-model.md` §8 and the `weakest` row: `evidence`, `stale` and `weakest` require only `Claim`; scoring fields `runs` and `held_out` apply to any cited target with defaults 0 and false; a Claim-and-Literature-only profile is a required fixture; no stored type is renamed. (T01, T04; decision 019.)
5. **SSE cursor.** Accepted. One opaque cursor `v1:<generation>:<seq>` with a random per-instance generation independent of `content_hash`, identical across Python, CLI and SSE (`id:` and `Last-Event-ID`); unknown, expired or previous-instance cursors reset. (T02, T07, T08, T11; decision 020.)
6. **Viewer profile metadata.** Accepted. A `profile` read returns the pinned profile as data (types in declaration order including unused ones, roles, gates with `when_fields`, no callables). The committee considered a shared read versus HTTP-only metadata. The maintainer selected the shared read across Python API, CLI, MCP and HTTP on 2026-10-21: 37 graph commands, not the HTTP-only/36-command alternative. (T02, T06, T11, T12, T13; decision 017.)
7. **Artifact download security.** Accepted. Downloads serve only registered artifact paths through `_safe_path` with containment preserved through opening, as inert attachments with `nosniff`; the launch token travels in the URL fragment and is exchanged once via `POST /api/session` for a host-only, `HttpOnly`, `SameSite=Strict` cookie; tokens are never accepted in query strings; `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, credentials excluded from logs; negative tests for traversal, symlink escape, unregistered files, foreign `Origin`/`Host` and active-content artifacts. (T02, T11, T12; decision 017.)

Disposition: the maintainer confirmed all recommended design choices on 2026-10-21; see the confirmations in `tasks/v0.2.md`. No new planning run is needed. The two agent products for Gate 2 have not yet been named. Design confirmation alone does not start implementation. Gate 2's real agent sessions, outside researcher session and cross-repository profile adoption remain distinct deliverables that local replay tests do not satisfy.
