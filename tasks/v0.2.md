# v0.2 work list (ordered)

Each item: what to build, and **done when**. One commit per item, message prefixed with the id. Items marked **[spec]** change `spec/` and carry the decision record named in the item (017 onward), written before the spec text in the same commit. Items marked **[decide]** name a choice the maintainer confirms before the commit lands.

## Maintainer confirmations — 2026-10-21

The maintainer accepted the reviewer's recommendations for all design choices
listed below. The existing `[decide]` markers identify those decision points;
they no longer mean these choices await confirmation. Record the choices in
ADRs 017–020 in T01/T02 before changing the normative specifications.

- Conditional activate gates and profile-extensible citation targets: accepted
  as specified in decisions 018 and 019.
- MCP: official Python SDK over stdio, fixed launch identity and role,
  server-enforced read-only mode, one tool per registry operation, default
  `full` preset and optional `essential` preset.
- HTTP/SSE: Starlette/Uvicorn in the optional viewer extra; core dependencies
  remain unchanged.
- Events: observed-state polling, in-memory restart-safe cursors and resets,
  with no durable event log or durable replay guarantee.
- Profile metadata: a read across Python API, CLI, MCP and HTTP. The inventory
  is **37 graph commands** (18 writes and 19 reads), excluding streams and
  servers. The HTTP-only/36-command alternative mentioned below is not selected.
- Viewer: framework-free custom element with plain ES modules and no bundler.
- Security: loopback server, fragment-token bootstrap to an HttpOnly session
  cookie, Host/Origin checks, and inert downloads of registered artifacts.

The two agent products for the real Gate 2 recordings have not been named;
their selection remains open and does not reopen these design choices.
These confirmations approve the design choices only; they do not start
implementation or authorize commits, pushes or external evaluation sessions.

**Inventory rule.** A new `rg` subcommand's row in `spec/operations.md` and its entry in `docs/user-manual.md` land in the commit that implements the command, never earlier, so `tests/test_docs.py`'s coverage check stays green at every commit. Semantics and acceptance scenarios may land earlier. Server launchers (`rg mcp`, `rg serve`) are documented in a separate "Servers" table, outside the graph-operation inventory. Each item that changes the installed command inventory updates `tests/test_docs.py` in the same commit (`spec_commands`, `help_commands`, `check_reference` and the counts in `test_manual_reference_matches_spec_and_real_installed_help`); these changes never wait until T16. Registry membership equals the Writes and Reads union; installed-command membership equals the disjoint union of Writes, Reads, Streams and Servers; every category keeps command, option and reference-field coverage with negative fixtures for missing, duplicate or misclassified entries. Passing means complete coverage, not retained obsolete assertions.

**Stack assumed** (decision 017; each **[decide]**): MCP over stdio with the official `mcp` Python SDK in an optional `mcp` extra; HTTP adapter and SSE on Starlette/Uvicorn declared as direct dependencies of an optional `viewer` extra; change events derived by polling the index's `content_hash` (the source fingerprint, distinct from the event-source generation) and diffing observed states, no file-watcher dependency; the viewer as one framework-free custom element `<research-graph>` in plain ES modules with no bundler, static files packaged in the wheel and served by `rg serve`; browser tests with Playwright in a `viewer` test extra on the CPython jobs only (as decision 016 did for the notebook). Core runtime dependencies are unchanged.
